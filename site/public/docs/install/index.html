How to install phonedriver

Install the phonedriver binary with one command on macOS, Linux or Windows, or build it from source, then check it with phonedriver doctor.

phonedriver is one binary: the CLI, the daemon and the MCP server. The Android agent is packed inside it, so there is nothing else to download.

Nothing is published yet. The commands under "One-line install" work once the first release is out. Until then, use "Build from source".

Fastest: npx

The phonedriver npm package is a small launcher. On first run it downloads the binary for your platform from GitHub Releases, checks its SHA-256 against the .sha256 file published beside it, caches it (~/Library/Caches/phonedriver/npm on macOS, ~/.cache/phonedriver/npm on Linux, %LOCALAPPDATA%\phonedriver\npm on Windows) and runs it. Later runs use the cache and make no network request. The launcher contacts GitHub only to download the binary and sends no telemetry. It needs Node 18 or later.

npx -y phonedriver --version
claude mcp add phonedriver -- npx -y phonedriver mcp

Permanent install

These put phonedriver on your PATH.

# macOS and Linux
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/hridaya423/phonedriver/releases/latest/download/phonedriver-installer.sh | sh

# Homebrew (macOS and Linux)
brew install hridaya423/tap/phonedriver
# Windows
powershell -ExecutionPolicy Bypass -c "irm https://github.com/hridaya423/phonedriver/releases/latest/download/phonedriver-installer.ps1 | iex"

The shell and PowerShell installers put phonedriver in $CARGO_HOME/bin (~/.cargo/bin) and add it to your PATH. The iOS Simulator runner needs no download: its sources are inside the binary, and the first command that needs it builds it on your Mac with Xcode and XcodeGen.

Build from source

Use Rust 1.99 or later.

cargo build --release

The build packs the Android agent, so it needs the Android SDK with build-tools **37.0.0** and platform **android-37.0** (ANDROID_HOME, falling back to ANDROID_SDK_ROOT), d8 and JDK 17. Override the versions with ANDROID_BUILD_TOOLS and ANDROID_PLATFORM. If anything is missing, the build says exactly what and how to get it. To skip that step, set PHONEDRIVER_AGENT_JAR to a built phonedriver-agent.jar (bash android-agent/build.sh makes one).

For iOS only, with no Android toolchain:

cargo build --release -p phonedriver --no-default-features

That binary has no Android support, and phonedriver doctor skips the Android checks. The binary is target/release/phonedriver.

Check it works

$ phonedriver version
phonedriver 0.1.0

phonedriver doctor checks adb, each Android device, the agent, UiAutomation, the video stream, Xcode, the simulators and the permissions of the daemon socket. Each line says ok, warn or fail, and a fix follows every line that is not ok.

$ phonedriver doctor
ok    adb server       0029 at 127.0.0.1:5037
warn  android devices  none connected
      fix: Connect a phone with USB debugging on, or start an emulator; `adb devices` lists what adb sees.
ok    xcode            Xcode 27.0, Build version 27A266a
ok    daemon socket    /Users/you/.phonedriver/run/daemon.sock mode 600 in a directory of mode 700

Environment variables

NameDefaultMeaning
PHONEDRIVER_HOME~/.phonedriverWhere the daemon keeps its socket, daemon.log, traces/, tmp/ and the iOS runner/ builds. Set it to run a separate daemon.
PHONEDRIVER_SOCKETunder PHONEDRIVER_HOMEThe daemon's socket or named pipe. Point it at an ssh -L forward to use another machine's devices.
PHONEDRIVER_DEVICEnoneThe device to use when --device is not given. Also read by phonedriver mcp.
PHONEDRIVER_SESSIONdefaultThe session name, as --session.
PHONEDRIVER_TEAMnoneApple developer team ID that signs the iOS runner on a physical device.
PHONEDRIVER_GUARDonoff stops the approval guard.
PHONEDRIVER_SECRETnoneThe text for type --secret, instead of stdin.
PHONEDRIVER_TRACE_FULL, PHONEDRIVER_TRACE_SCREENSoffKeep observation text, or screenshots, in traces.
ADB_SERVER_SOCKETtcp:127.0.0.1:5037The adb server to use, for example a tunnel to another machine.
