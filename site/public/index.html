Give your AI agent a phone.

phonedriver lets Claude Code, Codex, Cursor or any MCP client use an Android phone or an iPhone. The model opens apps, taps, types, scrolls and reads the screen. It reads the screen as text instead of screenshots: on an emulator, a 1,000-row screen comes back in 24 ms. After each tap it gets back only the lines that changed. And when it reaches a button labeled Pay or Place order, phonedriver stops and asks you.

claude mcp add phonedriver -- npx -y phonedriver mcp

Start an Android emulator, plug in a phone with USB debugging on, or boot the iOS Simulator. Then ask Claude: Open Settings and turn on Dark theme. Other clients, Homebrew and real iPhones: install guide.

+ marks a line that appeared, - one that left, ~ one that changed. The model doesn't need to poll or guess how long a screen takes to load. It takes a screenshot only when it needs to see a picture.

Speed

Measured on an Android 17 emulator, median of 50 runs, against adb shell uiautomator dump, screencap and input. The difference comes from a small helper process that phonedriver starts on the phone. It keeps the accessibility connection open, where adb starts a new process and writes XML each time. Method and raw data.

Asking before it pays

When a tap lands on a button labeled Pay, Buy now, Place order, Subscribe, Transfer or Delete account, phonedriver holds the tap and asks you in Claude Code's own prompt. The model never sees that question and can't answer it. In a client that can't show such a prompt, the tap waits and the model has to ask you in chat.

You choose Allow, Allow for this session, or Decline. If you want an agent to run without asking, you can say so in its instructions, and it passes autonomous: true; you can also turn the check off with PHONEDRIVER_GUARD=off.

The check reads button labels in English, Spanish, Portuguese, French, German, Italian, Dutch, Japanese, Chinese (Simplified), Korean and Hindi. It does not catch a payment button that is only an icon, or one labeled in another language. By default it asks about payments and deleting an account. To be asked about more, set PHONEDRIVER_ASK to any of send (Send, Reply, Post, Share), delete (Delete, Remove, Clear all) and install (Install, Uninstall), for example PHONEDRIVER_ASK=send,delete. The prompt says which kind of tap it is.

The model can't type plain text into a password field or a one-time code field. It gets an error that tells it to use secret, which keeps the text out of logs and traces.

Real jobs

I tested phonedriver on nine jobs done in apps' own screens. They included setting Chrome's search engine, cropping a photo, pinning and archiving Messages threads, finding the app that keeps the phone awake, and testing a sign-up flow for planted bugs. Each job ran twice with Claude Sonnet 5.5. A script checked the phone's own data afterwards, not the model's report. All 18 runs passed. On Android there is no app to install. phonedriver pushes its helper over adb when it connects. On iOS it builds a small XCTest runner on your Mac.

The MCP server has 14 tools: devices, apps, snapshot, screenshot, tap, type, swipe, scroll, press, launch, wait, batch, clipboard and shell. The phonedriver CLI has the same commands, for scripts and for agents that prefer a shell.

Limits

  • Tested on Android emulators (API 26 and 37), the iOS Simulator, an iPhone 14 Plus and an iPad Pro. Real Android phones use the same path but have had little testing. Bug reports from real phones are welcome.
  • A tap takes 70 to 120 ms on an Android emulator and 450 to 530 ms on a real iPhone.
  • The model can do anything on the phone you could do with your finger. For unattended runs, use an emulator or a spare phone.
  • phonedriver never enters a passcode and can't pass Face ID or a fingerprint check. Screens that block screenshots, as some banking apps do, come out black in a screenshot, though their text can still be read.

FAQ

How do I let Claude control my Android phone?

Run claude mcp add phonedriver -- npx -y phonedriver mcp, turn on USB debugging, and plug the phone in.

Does it work with an iPhone?

Yes, from a Mac with Xcode, on the Simulator or on an iPhone or iPad signed with your Apple developer team.

Can my agent buy things with it?

Not without your answer, unless you have told it to run autonomously. See Asking before it pays.

Can I use it at work?

Yes. It is AGPL-3.0: you can use it freely. If you change it and offer it to others as a network service, you must publish your changes.
