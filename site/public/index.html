@e1 PHONEDRIVER

Let your AI agent use a phone.

phonedriver gives an AI agent a text view of an Android or iOS screen and the means to tap, type and swipe. Every action returns only the lines that changed.

Free and open source (AGPL-3.0). CLI and MCP server. Up to 98 times faster than adb.

@e5

How a screen becomes text

A daemon keeps the device connection open, so each call costs milliseconds. On Android it pushes a small agent to the phone and starts it with app_process as the shell user, the way scrcpy does: nothing to install, no accessibility service to switch on. The agent reads the UI tree through UiAutomation and streams the display as H.264, so the daemon knows when the screen has stopped changing.

Refs such as @e10 are found again at tap time, so a list that shifted by a row still gets the right tap. How it reads a screen 98x faster than adb.

@e7

It asks you before it spends your money

An agent that can drive any app can place an order. phonedriver classifies the button the agent is about to tap. If the label says Place order, Pay, Send $20.00 or Delete account, the tool stops and asks the human through the MCP client, with the app, the button and the amounts on screen. Allow runs the tap. Decline does not.

The guard stops an agent that follows its rules or is steered by text on the screen. It does not stop an agent set on bypassing it, it reads English labels only, and a missing prompt is not proof a tap is safe. The design and its limits, and the setup guide.

@e8

Questions people ask

How do I let an AI agent control my phone?

Install phonedriver, add it to your agent as an MCP server (claude mcp add phonedriver -- phonedriver mcp for Claude Code), connect an Android phone with USB debugging, start an emulator, or boot the iOS Simulator, and ask the agent in plain language, for example "Open Settings and turn on dark mode." The agent gets a text view of the screen and tools to tap, type and swipe. See the setup guides.

How do I let Claude control my Android phone?

Add phonedriver to Claude Code as an MCP server with claude mcp add phonedriver -- phonedriver mcp, then connect a phone with USB debugging on or start an emulator. Nothing is installed on the phone. The device suite passes on emulators (API 26 and 37); a phone uses the same path and is not tested on hardware. See the Claude Code guide.

What is phonedriver?

phonedriver is a free, open-source CLI and MCP server that gives an AI agent a text view of an Android or iOS screen and the means to tap, type and swipe. Every action waits for the screen to settle and returns only the lines that changed, so the agent does not poll or sleep. It is licensed AGPL-3.0.

Which AI agents and MCP clients work with it?

Any client that starts a stdio MCP server can use it, including Claude Code and Cursor. Claude Code is the one we test against, with claude -p and Claude Sonnet 5.5 in our benchmarks. We have not run a Cursor session ourselves. The server has fourteen tools, and the CLI prints the same text as the MCP tools.

Does it work on a real iPhone and a real Android phone?

Yes for iPhone and iPad through the CLI and MCP, tested on an iPhone 14 Plus (iOS 26.1) and an iPad Pro (iOS 27.0); it needs a Mac with Xcode and a signing team. A real Android phone uses the same path as the emulator, over USB or Wi-Fi debugging, but we have not tested it on hardware yet. Android emulators (API 26 and 37) and the iOS Simulator are tested.

What is the fastest way for an AI agent to control a phone?

On an Android 17 emulator, phonedriver reads a 1,000-row list in 24.0 ms where adb takes 2,352.4 ms (98 times faster at p50, 95% CI 92.2 to 106.0), takes a screenshot in 11.6 ms against 476.3 ms (41 times) and types 100 characters in 251.1 ms against 4,840.9 ms (19 times). A bare tap is closer: 1.1 to 1.7 times faster host to reply. Emulator only; no physical phone has been measured. See the benchmarks.

How is phonedriver different from mobile-mcp and phone-harness?

mobile-mcp is an MCP server that reads the accessibility tree and also supports cloud devices, with anonymous telemetry on by default. phone-harness is a Python CLI that drives Android through adb and iPhones through Mac mirroring and OCR. phonedriver keeps a resident agent on the Android device, waits for the screen to settle after every action and returns a diff, asks before taps that spend money, and sends no telemetry. See the comparisons.

Can the agent spend my money or delete things?

Not without asking you. Before a tap on a button such as Place order, Pay, Send $20.00 or Delete account, phonedriver stops and asks the human through the MCP client, showing the app, the button and the amounts on screen. This stops an agent that follows its rules or is steered by screen text; it does not stop one set on bypassing it, and it matches English labels only. See the approval guard.

Does phonedriver send telemetry?

No. It talks to the device, the local daemon socket and the local adb server, and to Apple only when mounting an iOS developer disk image. A test runs the CLI, daemon and MCP server under a macOS sandbox that kills any process opening a non-local connection. Text passed with --secret never reaches logs, traces or replies. This website sets no cookies and runs no scripts.

Does it install anything on my phone?

On Android, no app and no accessibility service. The daemon pushes a small jar over adb and starts it with app_process as the shell user, the way scrcpy does. On iOS, a small XCTest runner is built on your Mac with Xcode the first time it is needed.

How many tokens does it use?

Its 14 MCP tools cost about 5,600 tokens on the first turn of a one-word claude -p, against about 5,200 for phone-harness. On three Android tasks, Claude Sonnet 5.5 used 218,357 tokens in total with phonedriver and 330,375 with phone-harness (medians of 2 to 3 runs, 34% fewer), all passing. Small samples: see the token benchmark.

What does it cost, and what is the license?

It is free. The license is AGPL-3.0-only: if you distribute phonedriver, or run a modified version as a network service, you must publish your source under the same license. The Android agent contains files copied from scrcpy under Apache-2.0.

What does it not do well yet?

A bare tap misses its 15 ms budget. An iOS tap takes 357 ms on the Simulator and 454 to 534 ms on devices. WebViews and custom views can have an empty accessibility tree, where it falls back to OCR. The real-phone jobs benchmark ran 2 passes per job on one tablet emulator, so its medians describe what happened and are not rates. Android hardware is untested.
