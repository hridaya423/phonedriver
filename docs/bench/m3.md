# M3: agent evaluation (task 4.5)

Runner: `bench/agent-eval/run.sh <tuning|heldout> <runs> <out-dir> [task]` (tasks in `bench/agent-eval/tasks.yaml`, checks and resets in the scenario runner's step language, `phone-use-bench eval ...`). Each run: reset the emulator state, a fresh `PHONE_USE_HOME` with `PHONE_USE_TRACE_FULL=1`, then `claude -p "<task>" --mcp-config <generated from mcp.json> --strict-mcp-config --allowedTools "mcp__phone-use__*" --tools "" --disable-slash-commands --setting-sources "" --model claude-sonnet-5-5 --output-format stream-json --verbose` from an empty directory (no CLAUDE.md, no skills, no built-in tools: the agent sees only the ten MCP tools and the server's one-paragraph instructions, not `SKILL.md`), kill the run's daemon, run the programmatic check, run cleanup. Device: `Pixel_API_37` (`emulator-5554`, `-gpu swangle_indirect`) on win-pc with two other emulators present. Tokens are input + output + cache creation + cache read as reported by the result event.

## App availability (checked before any held-out run)

Files (`com.google.android.documentsui`), Chrome (`com.android.chrome`) and Clock (`com.google.android.deskclock`) are installed on the API 37 image. No substitution was needed. The Compose tab of the testbed had one switch; it now has three (`compose_switch`, `_2`, `_3`, left to right) so "the third switch" exists.

What the transcripts showed and what changed:

1. `alarm-0730` failed in the first round: the agent called `devices`, saw three emulators and asked the user which one to use. The runner sets `PHONE_USE_DEVICE`, but nothing told the agent. `devices` now ends with `default device: <id> (used when \`device\` is omitted)` when a default is set. After: success, 10 calls (the Clock app's own screens).
2. `notification-code`: `launch` with the notification shade open returned success and a snapshot of the shade; the agent needed `press home` and a second `launch` (6 calls). The agent's `launch` and `open_url` ops now collapse the shade first (live test `launch_with_the_shade_open_shows_the_app_not_the_shade`, red then green). After: 4 calls, 37k tokens.
3. `testbed-row-640`: the tap answered `settled in 398ms` with no lines, and the agent spent calls on a snapshot and a screenshot to learn whether anything happened. A tap that redraws without changing any element now says `no element changed` (it already said `no change after Nms` when nothing redrew). The agent still screenshots, because the testbed's rows show nothing when tapped (they only log): the check passes, the agent cannot see it. Left as is.
4. `testbed-web-form`: a tapped web checkbox shows no checked state in the tree (`checkbox "Agree"`, state only `ENABLED`/`FOCUSED`), so the agent took a snapshot and a screenshot to confirm. Not fixed: the platform node of the WebView checkbox carries no checkable flag; open.
5. Also fixed on the way (found by the new three-switch test): siblings were ordered by fixed 8-point bands, so two controls whose centers straddled a band edge read in the wrong order (the first switch printed last). Rows now cluster by distance from the row's first center (`prune.rs`).
