## Failures and causes

| API 37 | testbed-web-form (4 of 6 runs in one batch) | the platform throws a NullPointerException from `AccessibilityNodeInfo.getChild` while a WebView builds its tree | `walk` treats the child as absent; 7 of 8, then 8 of 8 in later batches |

## Environment findings

- The win-pc emulators died or hung 6 times in about 12 hours; five of the six coincide with the first use of a WebView (Chrome, or the testbed's web tab). The stock-app scenario that used Chrome (`chrome-open-page`, first-run screens dismissed, page text `Example Domain` asserted) passed on API 37 in 2 of 2 and killed the emulator in the third run; it was moved to `bench/scenarios/android-unstable/` and replaced by `settings-battery`.
- Two emulators running at the same time coincided with the deaths; the API 26 final runs were made with the API 37 emulator stopped.
- A fresh cold boot of the API 37 image needs several minutes before `System UI` answers.
